# REQUIREMENTS.md — حجوزاتي (Hajozati)

## Functional Requirements

### Authentication
- تسجيل حساب جديد (بريد/هاتف + كلمة مرور، قابل للتوسع لاحقًا لـ OTP أو OAuth).
- تسجيل الدخول / تسجيل الخروج.
- استمرارية الجلسة (Persisted Session).
- وضع "دخول كضيف" (Guest Mode) اختياري للتصفح قبل الحجز (قرار يُحسم لاحقًا في DECISIONS.md).

### Home
- عرض بطاقة بحث مركزية (Search Card): محافظة، تاريخ وصول، تاريخ مغادرة، عدد بالغين، عدد أطفال، زر بحث.
- عرض مختصر لعروض/وجهات مقترحة (لاحقًا).
- الوصول السريع إلى: حجوزاتي، المفضلة، اكتشف العراق.

### Search
- اختيار محافظة من قائمة محافظات العراق (بيانات منفصلة عن الواجهة).
- اختيار تاريخ الوصول والمغادرة عبر Date Picker مع تحقق (المغادرة بعد الوصول).
- اختيار عدد البالغين (حد أدنى 1) وعدد الأطفال (حد أدنى 0).
- تحقق من اكتمال الحقول قبل تفعيل زر البحث.

### Search Results
- عرض قائمة فنادق مطابقة للمعايير: صورة، اسم، محافظة، موقع، تقييم، أقل سعر، عدد الغرف المتاحة.
- حالات: تحميل (Loading)، نتائج فارغة (Empty)، خطأ (Error) مع إعادة محاولة.
- بنية جاهزة لإضافة Filters (سعر، تقييم، خدمات، نوع غرفة، مسافة) لاحقًا.
- فتح تفاصيل الفندق عند الضغط على العنصر.

### Hotels
- صفحة تفاصيل فندق: صور، اسم، تقييم، وصف، محافظة، عنوان، موقع على الخريطة، خدمات، سياسات، قائمة الغرف المتاحة.
- الانتقال إلى اختيار غرفة محددة.

### Rooms
- عرض قائمة غرف الفندق المتوفرة ضمن تواريخ البحث.
- تفاصيل الغرفة: نوع، سعة، أسرّة، سعر، خصم إن وجد، خدمات، سياسة الإلغاء.
- اختيار غرفة ينقل المستخدم إلى تدفق الحجز.

### Booking
- إنشاء وإدارة "Booking Draft" مركزي يحافظ على بيانات الحجز عبر الشاشات (فندق، غرفة، تواريخ، ضيوف، بيانات النزيل، السعر، الرسوم، الإجمالي).
- شاشة إدخال بيانات الحجز (بيانات النزيل الأساسية).
- شاشة مراجعة الحجز قبل التأكيد (ملخص كامل).
- شاشة تأكيد الحجز.

### Booking Confirmation & QR
- إنشاء رقم حجز فريد (Booking Reference) عند التأكيد.
- توليد QR Code يمثل بيانات الحجز (كقسيمة حجز).
- عرض شاشة تأكيد نهائية بعد الحجز.

### My Bookings (حجوزاتي)
- ثلاث حالات: Upcoming, Completed, Cancelled.
- فتح تفاصيل أي حجز سابق أو قادم.

### Favorites
- إضافة/إزالة فندق من المفضلة.
- عرض قائمة المفضلة والانتقال منها إلى تفاصيل الفندق.

### Nearby Hotels
- عرض فنادق قريبة بناءً على موقع المستخدم.
- التعامل الكامل مع حالات الصلاحية: منح، رفض، رفض دائم، تعطيل الموقع، تحميل، خطأ، إعادة محاولة، نتائج فارغة.

### Explore Iraq
- عرض قائمة وجهات/أماكن سياحية: صورة، اسم، محافظة، وصف، موقع، تفاصيل، وفنادق قريبة من الوجهة.

### Profile
- عرض/تعديل بيانات المستخدم الأساسية.
- الوصول إلى حجوزاتي والمفضلة.
- تغيير اللغة، إعدادات الإشعارات، الإعدادات العامة، تسجيل الخروج.

### Notifications
- بنية جاهزة لإشعارات الحجز (تأكيد، تذكير، تغييرات) — التنفيذ الكامل لاحقًا (Phase 18).

### Localization
- دعم كامل للعربية (RTL) والإنجليزية (LTR) من اليوم الأول.
- بنية نصوص (ARB/JSON) قابلة للتوسع لإضافة الفارسية لاحقًا دون تعديل هيكلي.

### Maps
- عرض موقع الفندق على خريطة ضمن تفاصيل الفندق.
- استخدام الموقع الجغرافي لميزة الفنادق القريبة.

### Hotel Partner (مستقبلي)
- دخول مخصص لمدير الفندق.
- إدارة الفندق، الغرف، الأسعار، التوفر، الصور، الحجوزات، العروض.

### Admin (مستقبلي)
- إدارة المستخدمين، الفنادق (قبول/رفض)، الحجوزات، الوجهات، المحتوى، الإشعارات، التقارير، الإحصائيات.

### Backend (مستقبلي)
- واجهات API لكل الميزات أعلاه (راجع API_CONTRACT.md).
- قاعدة بيانات مركزية (راجع DATABASE_SCHEMA.md).

## Non Functional Requirements

### Security
- عدم تخزين كلمات مرور أو بيانات حساسة بنص صريح.
- التحقق من صلاحية الجلسة قبل عمليات الحجز.
- فصل صلاحيات المستخدم/مدير الفندق/الأدمن (Role-Based Access) معماريًا منذ البداية.

### Performance
- زمن استجابة واجهة سلس (60fps) وعدم حجب الـ UI أثناء الجلب.
- Skeleton Loading بدل شاشات فارغة أثناء التحميل.
- تخزين مؤقت خفيف للبيانات شبه الثابتة (كالمحافظات) لتقليل الاستدعاءات المتكررة.

### Accessibility
- تباين ألوان كافٍ (متوافق مع Design System).
- دعم أحجام خطوط ديناميكية عند الإمكان.
- عناصر تفاعلية بحجم لمس مناسب (حد أدنى 44x44).

### Localization Quality
- عدم وجود نصوص Hard-coded داخل الواجهات؛ جميع النصوص عبر نظام ترجمة مركزي.
- اختبار كامل لاتجاه RTL في جميع الشاشات.

### Maintainability
- Feature-based Architecture مع فصل واضح بين الطبقات (راجع ARCHITECTURE.md).
- تغطية اختبارات لكل Feature قبل اعتباره مكتملًا (راجع Definition of Done في DEVELOPMENT_ROADMAP.md).
